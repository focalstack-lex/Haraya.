## Why it is blocked

The frontend code is in good shape; the blockers are the live database and hosting configuration. The two
most important: Add a Spot is in the code but its database protections are not live, and sign-in is now open to
anyone while `cup_checks` still accepts unbounded, unthrottled inserts.

## Proposed fixes (not applied)

1. Apply `supabase/migrations/20260929000000_spot_submissions.sql` (and confirm `20260928230000` is applied).
2. New migration: since Cup Check is hidden, revoke `insert` on `cup_checks` from `authenticated` (drop the
   insert policy) until the feature returns with length checks, a server-set `user_name`, and a rate limit. Add
   `char_length` checks on `profiles.name` and `business_name`, and a per-user cap on `cafe_saves`.
3. `vercel.json` headers: CSP allowing self, Google Fonts, OpenStreetMap tiles, Supabase and Open-Meteo;
   `X-Content-Type-Options: nosniff`; `frame-ancestors 'none'`; `Referrer-Policy: strict-origin-when-cross-origin`;
   `Permissions-Policy: geolocation=(self), camera=(), microphone=()`. Import Leaflet CSS from the npm package
   instead of unpkg.
4. Set `HABI_URL` to the real production URL or hide the switcher; remove `public/mascot/*.jpg`.
5. Delete `scripts/seed-supabase.ts`, or rewrite it to refuse production URLs and seed nothing fake.
6. In Supabase Auth: confirm email rate limits, and set custom SMTP before launch (the built-in sender is for
   testing and is heavily limited).
