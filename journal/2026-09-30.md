## Why a new account had no profile row

- Question from Lex: creating an account left no row in `public.profiles`.
- Root cause: the row is made by a database trigger (`on_auth_user_created` on `auth.users`, calling
  `handle_new_user`), and the only migration that creates that trigger is `20260929000000_spot_submissions.sql`
  (line 169). `20260929020000` only replaces the function and relies on the trigger already existing. That first
  migration was never applied to the live project: probing it with the public key, `spot_submissions` and
  `place_applications` do not exist (PGRST205) and `admin_set_profile_role` and `admin_review_place_application` are
  missing (PGRST202), while `profiles`, `cafes`, `cafe_saves`, `cup_clinks`, `is_admin` and `sanctuary_visits`
  exist. So sign-up worked in Supabase Auth and nothing wrote the profile. The app is not at fault: `loadProfile`
  reads the row and treats a missing one as "no profile".
- Consequences while it was missing: no name, role or status for the account (role checks, the Place Portal and
  Control Room), and any statistic that updates the profile has nothing to update.
- Fix: `supabase/migrations/20260930000000_profile_on_signup.sql`, standalone and idempotent: the latest
  `handle_new_user` (guest, approved, name from sign-up metadata cut to 80 characters), the trigger, and a backfill
  for accounts created without one. Needs running on the live project by its owner.
- Verified on a real PostgreSQL (PGlite) with the project's `profiles` table and a stand-in `auth.users`: 2 accounts
  and 0 profiles before; after the file both have a row (names kept, blank stays blank for a Google account); a new
  sign-up gets its row at once with the trimmed name; a 200-character name is cut to 80; an account with no email
  still gets a row; running the file again adds nothing and keeps an edited role and name; the trigger is listed.
- Still pending on the live project and unrelated to this fix: migrations 20260929000000, 010000 and 020000 (Add a
  Spot, place applications, the admin functions).
