## Landing page: Forward and typed app addresses now leave it

- Found while checking the merged map in the preview pane: opening `/` and then going to `#/tab/map` kept showing
  the landing page. Root cause, present since the landing page was added on 2026-09-29 (not from the merges): the
  hash route handler in `App.tsx` set the tab but never cleared `isLanding`; only `setActiveTab` did. So the browser's
  Forward button from the landing, or a typed `#/tab/...` or `#/cafe/...` address, changed the URL without leaving it.
- Fix: `apply()` clears `isLanding` for any app route (`route.kind !== 'none'`).
- Verified with Playwright on the dev server: landing, Open Haraya, Back (landing), Forward (Discover), typed
  `#/tab/map` (Map & Spots), `#/cafe/digos-the-nook` from the landing (sheet opens), 0 page errors. `npx tsc -b`
  clean, tests and oxlint pass. Evidence script in `reports/ui-verification/2026-09-30-landing-forward/`.
